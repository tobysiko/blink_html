# Blink — playable app (v0.22)

`../Blink-play-v0.22.html` is the deliverable: one self-contained file, no server,
no network. Double-click it. You play one seat; the rest are run by the tuned
v0.22 bot.

## Source layout

| file | what it is |
|---|---|
| `engine.js` | the rules, ported from `../sim/engine.py` at the v0.22 defaults |
| `ui.js` | rendering and input only — it contains no rules |
| `shell.html` | markup and CSS, with `/*__ENGINE__*/` and `/*__UI__*/` placeholders |
| `build.js` | inlines the two scripts into `../Blink-play-v0.22.html` |

Rebuild after any edit:

```
node build.js
```

## How the human seat works

Every method in the engine that needs a decision is a **generator**. A bot seat
answers inline; a human seat *yields a request* and is resumed with the answer:

```js
const it = game.playRound();
let r = it.next();
while (!r.done) r = it.next(answerFor(r.value));
```

There is one code path for both, which is the point — the options offered to a
person are generated by the same functions that constrain the bot, so no
illegal move can be presented.

**The map phase is one open turn.** Rather than marching the player through a
fixed sequence, the engine yields a single `turn` request carrying everything
still legal, recomputed after every action:

```js
{ cards: [{card, options:[[cell,'settle'|'explore'|'attack'], …]}, …],
  moves, moveSources, canResearch, researchBlocked,
  colonyCards, cashCards, fortifyCells }
```

The player spends cards, moves, fortifies, researches, founds colonies and
cashes victory cards in any order, then answers `{kind:'end'}`. Requests are
`meld`, `turn`, `bonus`, `discard`, `gridslot`, `buy`, `retire`, `effectA`,
`feed`, `waterexplore`.

**Bot seats keep the old fixed order** (`_place` → recycle → research → B → C →
moves → fortify), so `verify.js` still measures the same engine the sim
measures. The free-form turn is a human affordance, not a rules change.

**Research is shown as one action, not a chain of prompts.** Clicking Research
opens a preview listing all three steps and the cost; nothing is spent until
"Begin research". From then on every step renders inside the same panel with
✓ / ▸ / · progress and what each step produced, and it closes with an explicit
completion line. The steps are irreversible once begun — the draw has happened
and the turn's research is used — so the preview says so before you commit.

Two constraints the open turn has to enforce that a fixed sequence got for free:

- **Research is spent when taken, not when it succeeds.** An attempt that finds
  nothing under your rank cap still drew a card onto the grid, and the deck is
  the game's clock — retrying would thin it for free.
- **The hand refills only once the meld is fully resolved.** Recycling with
  cards still on the table would swap the discard into hand and then take those
  cards back on top of it, over the ten-card ceiling.

**Policy is not rule** — this has now bitten three times. Besides effects A and
B below, `_resolve` contained the bot's HOLD-BACK policy: take a coin rather
than climb into a tier you cannot feed. Shared between bot and human, it turned
a person's chosen Settle into 1 gold with no explanation — two cards on one
Plains tile, one unit appears. Hold-back is now bot-only. Anything in the engine
that decides *whether to do the thing the player asked for* is suspect.

**Policy is not rule.** The Python bot declines effect A unless its row holds
three cards and its meld is two cards or fewer, and declines B below four cards.
Those are the bot's heuristics, tuned for measurement. A human is offered A and
B whenever the *rules* allow, and the bot keeps its guards, so the sim's numbers
stay comparable. One consequence worth watching at the table: a person taking
research every single turn banks far more victory row than the guarded bot does,
so the bots may now feel soft.

## Cards

One face, three sizes, built by `faceInner()` in `ui.js`:

| size | where | shows |
|---|---|---|
| `mini` | a rival's meld, the drawn card in a sentence | rank + suit letter |
| `mid` | your hand, victory-row slots, the market | terrain band, rank, and a one-line `+1 card · 2g` effect strip |
| `full` | the victory-card panel | all three effects, as the physical card prints them |

The effect text comes from `effectText(rank)` in `engine.js`, lifted verbatim
from `source/Blink-card-effects.html`, so the app and the production reference
cannot drift. All four suits of a rank share the same effects; suit only matters
for B's terrain.

**The victory row is the interface for A/B/C.** Clicking a card in your row
opens its full face with the three effects as buttons, each live or greyed with
the actual reason ("card phase only", "one victory card on colonies per turn",
"no Forest tiles left in the supply"). This replaced a `Colonies (B)` and a
`Cash a victory card (C)` button that named neither the value nor the cost — a
player had no way to learn that a card in the row is a choice between winning a
trick, founding colonies, and gold.

The effect strip on **hand** cards exists for the retire decision: what a card
will be worth once it is in the row is exactly what you are judging when you
choose which to retire.

## Map scale

`ZOOM` in `ui.js` is pixels per engine unit and defaults to `0.5` — a hex is 30
units, so 15 px of radius. The map is fitted to its panel but never scaled
*above* `ZOOM`, which is why a six-tile opening board no longer fills the screen.
Large boards hit the fit limit and shrink normally. The − / + buttons on the map
adjust it between 0.25 and 1.1.

## Opening it on a phone

**iOS Files does not run JavaScript.** Tapping the file in Files opens it in
Quick Look, which renders the markup but never executes scripts — so the seat
list (built by script) is empty and Start (whose handler is attached by script)
does nothing. Nothing is wrong with the file.

The page now says so itself: `#nojs` is visible by default and is hidden by the
first line of the bundle, `document.documentElement.className += ' js'`. If that
line never runs the notice stays up and the setup form is hidden, so the failure
explains itself instead of looking like a broken page. `nojs_test.js` asserts
both states.

To actually play on a phone, the file has to be served to a real browser:
put it on any static host (GitHub Pages works) and open the link in Safari, or
open it from an app with a built-in browser such as Documents by Readdle.

## Tests

```
node smoke.js        # 180 bot-only games: unit, tile and connectivity invariants
node human_test.js   # 240 games with a scripted human seat; all 14 request types
node verify.js       # 900 bot-only games, 16 metrics, to diff against the sim
```

These three need nothing but node. The two that drive the real interface need
jsdom (`npm install jsdom`; nothing else in the project depends on it):

```
node visible_test.js         # asserts the app is VISIBLE after Start
node nojs_test.js            # the no-JavaScript notice appears, and only then
node ui_playthrough_test.js  # clicks four games to completion through the DOM
```

`visible_test.js` exists because of a bug it would have caught and the others
did not. `startGame` used `style.display = ""` to reveal `#game`, which clears
the *inline* style and lets the stylesheet's `#game{display:none}` win — a
blank page. Every DOM-querying test passed, because the elements were all built
correctly and merely invisible. Assert computed visibility, not presence.

`ui_playthrough_test.js` earns its keep the same way: it was the thing that
noticed Research could be pressed repeatedly in one turn, because a scripted
clicker will happily press a button 32 times a game when a person would not.

`verify.js` prints the same metrics as `sim/_verify.py` run with
`bot=pro_bot, smart=True, pro=all seats`. The two engines use different random
number generators, so games never match card for card; agreement is
distributional. Over 300 games per player count:

| | 2p JS / PY | 3p JS / PY | 4p JS / PY |
|---|---|---|---|
| final score | 44.28 / 44.23 | 37.62 / 37.88 | 29.08 / 29.80 |
| population | 18.75 / 18.84 | 17.43 / 17.48 | 15.78 / 15.95 |
| victory row | 19.06 / 18.97 | 15.90 / 16.12 | 10.00 / 10.59 |
| dominance | 6.47 / 6.42 | 4.29 / 4.29 | 3.30 / 3.26 |
| rounds | 12.59 / 12.23 | 14.48 / 14.43 | 16.77 / 16.42 |
| settles | 40.18 / 39.76 | 60.57 / 60.57 | 86.04 / 85.33 |
| kills | 8.70 / 7.96 | 15.66 / 15.18 | 30.04 / 28.87 |
| upgrades | 20.74 / 20.07 | 29.61 / 29.35 | 32.89 / 32.99 |

The widest gaps are free moves (JS ≈7% lower at 3–4p) and colony tiles, both
high-variance counters; every score component agrees within about 3%.

## Responsive layout

Two breakpoints in `shell.html`:

- **≤ 900px** — the sidebar stops being a sidebar. Everything stacks in reading
  order (map, what everyone played, your cards, the market, then rivals and the
  log), the page scrolls, and the map takes a fixed 42vh instead of a grid row.
- **≤ 560px** — the tier rows drop their food and free-move columns, cards
  shrink, seat cards go full width, End turn goes full width.

**Not verified visually.** jsdom does not evaluate media queries or implement
`matchMedia`, so the tests can only confirm the rules exist and that every
desktop-only assumption (`body{overflow:hidden}`, the two-column `.wrap`, the
fixed `#game` height, `.lower`'s max-height) is overridden below 900px. The
actual phone rendering wants a look on a real device.

## Known gaps

- **Expansions are not implemented.** No Wasteland/Disaster, no trade, no map
  objectives — base game only, as in the sim.
- **Optional variants are not implemented**: combination melds, super melds,
  friends of 10s. They are flags in `sim/engine.py` and would each be a small
  addition to `enumerateMelds`.
- **No solo Automa.** `Blink-solo-mode-v0.1` is a separate design.
- The starting draft is played for you (the bot's `draftPick`). Drafting by
  hand would be the next thing worth exposing, since it is a real decision.
- Bots resolve instantly with no animation; the log names the trick winner and
  the map redraws, but a fast bot turn can be easy to miss.
