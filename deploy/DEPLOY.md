# Putting the prototype online

`index.html` in this folder is the built, minified page with the meta tags a
served copy wants. It is regenerated by `app/build.js`, so edit the sources in
`app/` and rebuild — never edit this file by hand.

## Why you have to run the deploy

The Vercel connector deploys a file tree passed **inline in the request**. The
page is 77 KB of minified JavaScript; that cannot be retyped reliably, and a
single wrong character would break the game silently rather than loudly. So the
transfer is yours; everything else is done.

## One command

```
cd "<this folder>"
npx vercel deploy --prod
```

First run asks you to log in and to name the project — call it **blink-play**,
and accept the defaults (no framework, no build command; it is a static file).
You get a URL like `https://blink-play.vercel.app`.

Alternative with no CLI: go to **vercel.com/new**, drag this folder in, deploy.

## Do NOT deploy into the `deep-diversions` project

That project serves deep-diversions.com and is Git-connected. A file-tree deploy
containing only this page would replace the whole site, and the site's source is
not here to redeploy alongside it. Keep the game in its own project and point a
subdomain at it.

## Then: blink.deep-diversions.com

In the Vercel dashboard, on the **blink-play** project:

1. **Settings → Domains → Add**
2. Enter `blink.deep-diversions.com`
3. Vercel shows one DNS record to create. Because `deep-diversions.com` is
   already a Vercel domain on the same account, it usually offers to add the
   record itself — accept, and it is live in a minute.
4. If it asks you to add it manually, the record is a `CNAME` on the host
   `blink` pointing at `cname.vercel-dns.com`.

Nothing about deep-diversions.com itself changes: you are adding a subdomain,
not touching the apex or `www`.

## Before you share it widely

- The page carries `<meta name="robots" content="noindex">` while it is a
  prototype. Remove that line in `app/build.js` when you want it found.
- The **mobile layout has never been seen rendering.** jsdom cannot evaluate
  media queries, so the phone breakpoints are verified structurally only. Open
  it on your own phone first.
- Every game runs entirely in the browser. No network calls, no storage, nothing
  to collect — so there is no privacy surface to think about before sharing.

## Checking it worked

Once it is up, the fastest check that scripts are running — the thing that
failed in iOS Files — is that the **seat list is populated** and **Start** works.
If you see the amber "This page needs JavaScript" panel, the file was served but
the script did not run.
